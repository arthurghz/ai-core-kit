## 0. The one thing to never get wrong: two layers

`ai-core-kit` is **not a project — it is the standard every new project forks.**
It is a meta-repo that, via a single `/init` run, installs a battle-tested Claude
Code configuration + a delivery methodology into a fresh child repo.

| Layer | What it is | Rules that live here |
|---|---|---|
| **META** — building `ai-core-kit` itself | the scaffold repo, its templates, its orchestration | forkability, idempotency, discovery engine, telemetry, template hygiene |
| **CHILD** — what `/init` *generates* into a fork | the actual new project | design-contract-first, the bootstrap interview, archetype scaffolding, the contract gate |

**Design-contract-first / API-first / the contract gate are CHILD-layer rules.**
They are authored in `ai-core-kit` as *templates + hooks that ship into the child*,
**NOT** as rules governing how you build `ai-core-kit`. Building the meta-repo =
building the machine that stamps out that standard.

**Current focus:** the **Claude Code layer** (`.claude/` tree, commands, agents,
skills, hooks, templates, MCP wiring).

## 2. Canonical conventions (make these the standard)

- **SKILL.md frontmatter** = `name` (lowercase-hyphenated) + `description`
  (third-person: *what it does + when to use it*, with trigger phrases & when-NOT-to-use).
  Optional: `license`, `allowed-tools`. **Reject** `version/author/category/triggers/updated` in frontmatter.
- **500-line body cap** on SKILL.md; push detail to `references/*.md`, templates to
  `assets/`, automation to `scripts/`. **Reference files linked one level deep only.**
- **Layout:** `.claude/{agents,commands,skills,hooks}` + `settings.json`
  (+ git-ignored `settings.local.json`); folder-per-skill; `.claude-plugin/` for plugin metadata.
- **Architecture spine = Command → Agent → Skill.** Commands are thin entrypoints;
  **logic lives in skills**, not commands.
- **Agent contract:** markdown + YAML frontmatter (`name`, `description` with "use
  proactively when…", `model: haiku|sonnet|opus|inherit`, `tools` allowlist). Body =
  single objective, explicit output format, tool/source scope, done-criteria. One agent
  per focused task; agents orchestrate skills, don't duplicate them.
- **Hook exit-code contract:** `0` = ok, `2` = block (stderr fed back to model),
  other = non-blocking. Use `${CLAUDE_PROJECT_DIR}` for portable paths.
- **CLAUDE.md = minimal pointer file** to on-demand `build.md`/`testing.md`/`conventions.md`.

## 3. Corrections to a naive plan (these change the build)

1. **Hooks are OPT-IN, not baseline.** 2 of 4 reference repos ship zero hooks; blocking
   hooks wedge sessions. Gate them via the interview; ship conservative matchers; document `disableAllHooks`.
2. **Hook footgun (load-bearing):** a blocking `PreToolUse` hook **must** use **exit code 2**
   (not 1) and set **`hookSpecificOutput.permissionDecision: "deny"`** (not a top-level
   `decision`). Wrong form silently no-ops the guard. Bake this into the gate template.
3. **Telemetry hooks can't read token cost today** (issue #11008). `PostToolUse` JSONL =
   **activity/metadata only**; real **cost attribution comes from an offline transcript
   aggregator** over `~/.claude/projects/**/*.jsonl` + a **versioned pricing map**.
   `PostToolUse` must never exit non-zero (its stderr leaks to the model).
4. **Agent teams = experimental & expensive** (env-flagged, no resume, no nested teams) →
   advisory **decision rule**, not default wiring. Default to subagents for report-back workers.
5. **CLAUDE.md bloat = permanent per-turn token tax** → minimal pointer file.
6. **MCP scope = credential-leak risk** → project `.mcp.json` (committed) for shared servers,
   local `~/.claude.json` for credentialed ones; always fully-qualify `Server:tool` names; set per-server `timeout`.
7. **`/init` must branch** on hooks / MCP / agent-teams / SDD-gating (opt-in toggles).
   Always-on safe core = skills + minimal CLAUDE.md + command/agent conventions.

## 6. TEAMS execution command (run this in a fresh chat)

### 6a. Paste this prompt to drive the build with teams
```
Act as lead orchestrator for ai-core-kit (read docs/BOOTSTRAP.md for full context).
Build it with MULTIPLE AGENT TEAMS, one workflow per phase, stopping at each ✋ gate
for my approval. For EVERY phase use multiple agents that (1) git clone the reference
repos into a scratch dir for exact extraction, (2) verify each .claude/ primitive
against docs.claude.com, (3) author files, (4) a QA agent validates against the
acceptance tests. Never conflate the META and CHILD layers. Start with Phase 1.
```

### 6b. Workflow skeleton (one phase = one team; pattern to reuse per phase)
```js
export const meta = {
  name: 'ai-core-kit-phaseN',
  description: 'Build phase N of ai-core-kit with a multi-agent team',
  phases: [{ title: 'Ground-truth' }, { title: 'Author' }, { title: 'QA' }],
};
const SCRATCH = '/tmp/ack-refs';
// 1) Ground-truth: clone repos + verify docs (parallel, barrier)
phase('Ground-truth');
const facts = (await parallel([
  () => agent('Clone anthropics/skills + 3 MIT repos into '+SCRATCH+'; extract exact SKILL.md/agent/command/hook conventions + licenses. Report paths+quotes.', {phase:'Ground-truth'}),
  () => agent('WebFetch code.claude.com/docs/en/{hooks,sub-agents,slash-commands,skills,mcp}; quote exact specs for the primitives this phase authors.', {phase:'Ground-truth'}),
])).filter(Boolean);
// 2) Author each artifact of the phase (parallel or pipeline), grounded in facts
phase('Author');
const artifacts = await parallel(PHASE_ARTIFACTS.map(a => () =>
  agent('Author '+a.path+' for ai-core-kit. Spec: '+a.spec+'. Ground-truth:\n'+facts.join('\n---\n'), {label:'author:'+a.path, phase:'Author', isolation:'worktree'})));
// 3) QA: validate against acceptance tests; adversarially verify
phase('QA');
const qa = await agent('Validate the phase artifacts against the acceptance tests; list any failures with fixes.\n'+JSON.stringify(artifacts), {phase:'QA'});
return { facts: facts.length, artifacts, qa };
```

## 7. Acceptance tests (definition of done)

1. **Fork → `/init` per archetype** produces a working, project-specific setup (correct
   templates, contract template, gate active in chosen mode, MCP wired, tailored
   `CLAUDE.md` + `project.manifest.yaml`), zero manual file shuffling.
2. **Interview branches** — IaC never asked DB Qs; fullstack triggers design-system install.
3. **Gate modes** — `block` refuses `src/**` edits w/o approved contract; `warn` allows-with-warning; `off` silent. No hook code change between modes.
4. **Discovery** — `/discover --scan` emits ≥1 well-formed proposal, adopts nothing.
5. **Telemetry** — after an orchestrated run, `telemetry-mcp session_summary` returns a
   non-empty cost breakdown attributed by feature and agent.
