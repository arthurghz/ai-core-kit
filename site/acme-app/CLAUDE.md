This file is the entry point Claude Code reads on every turn. It is deliberately
a **lean pointer**, not a knowledge dump: it tells Claude *where the truth lives*
and *how to work here*, then gets out of the way. The truth lives in the **specs**
(narrative Markdown) and the **contracts** (the approval oracle). Read the spec
before you write code — in this project, **specs lead and code follows**.

## How to work here

1. **Read the spec first.** The `specs/` documents below are the source of intent.
   Before implementing anything, read the relevant spec section; if it is empty or
   stale, fill it (or run `/ack-spec`) *before* writing code — never the reverse.
2. **Least code.** Prefer the smallest change that satisfies the spec. Do not add
   speculative abstractions, frameworks, or files the spec does not call for.
3. **Keep specs and code in lockstep.** When behavior changes, update the spec in
   the same change. A diff that alters behavior without touching `specs/` is incomplete.
4. **Respect the contract gate** (see below). Edits under protected paths are
   gated on an *approved* contract; do not work around the gate.
5. **Follow the conventions.** House style, naming, and review checklist live in
   `.claude/conventions.md` and the project skills under `.claude/skills/`.

## Contracts & the gate

@docs/contracts/

Contract gate: **block** (glob dialect `fnmatch`).
A contract in `docs/contracts/<id>.contract.md` is the gate's *approved?* oracle:
an edit under a protected path is allowed only when a contract whose `scope`
covers that path has `status: approved`. Protected paths:

- `app/**`
- `api/**`
- `src/**`
- `prisma/schema.prisma`

To change something under a protected path: author or update the governing
contract, get it to **approved**, then implement. `/ack-spec` can seed the first
contract from the specs above.
