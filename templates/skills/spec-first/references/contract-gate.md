# The contract gate — approve, then edit

The contract gate is how spec-first enforcement bites. It is a `PreToolUse` hook
(`.claude/hooks/contract-gate`) configured from the project manifest. It turns the
specs into *enforced* intent for the paths that matter most.

## How it decides

For an edit to a file:

1. If the path matches an **exempt** glob → **allow** (exempt wins over everything).
2. If the path matches a **protected** path (or a contract `scope`) → allow only
   when a contract whose `scope` covers it has `status: approved`. Otherwise the
   gate **mode** applies: `block` (refuse), `warn` (allow + warn), or `off`.
3. If the path matches nothing → **allow** (unmatched files are not gated).

A contract is a Markdown file in `docs/contracts/<id>.contract.md` with an `id`
(pattern `C-NNN-<slug>`), a `scope` (glob list it governs), and a `status`
(`draft` → `proposed` → `approved` → `rejected`). The manifest's
`managed.contracts[]` mirrors these as the gate's *approved?* oracle.

## The loop: approve, then edit

To change something under a protected path:

1. **Find or author the governing contract.** `/ack-spec` can seed one
   (`C-001-<slug>`) with a scope inferred from the specs. Its body says *what we
   are committing to* — the interface, invariants, and acceptance criteria, drawn
   from `specs/DOMAIN.md` and `specs/REQUIREMENTS.md`.
2. **Get it approved.** A human moves the status to `approved` (and re-runs
   `/ack-init` so the manifest oracle reflects it). Approval is the gate — not
   generation.
3. **Implement** the change under the now-covered path.

Do **not** route around the gate (renaming files, widening exempt globs to dodge
review, flipping mode to `off` to "unblock"). If the gate is in the way, the
honest move is to author/approve the contract — that is the point of spec-first.

## Relationship to the specs

The contract is the *enforced, approved* slice of the spec. The specs describe
the whole intended system; a contract pins down a governed surface and records
that a human has signed off on changing it. Keep them consistent: a contract's
invariants and acceptance criteria should trace back to `specs/DOMAIN.md` and
`specs/REQUIREMENTS.md`. If the spec changes a governed behavior, the contract
must be re-reviewed.

## Tuning

The gate's `mode`, `protected_paths`, `scope`, and `exempt` are manifest-owned
and regenerated by `/ack-init`. Change them through the interview / manifest, not
by hand-editing the managed block in `CLAUDE.md`. Start in `warn` while specs are
still settling, then move to `block` once the protected surface is real.
